# Қаржы менеджері — 1–4 зертханалық жұмыс

Python 3.11+ және Streamlit. Интерфейс қазақ тілінде, сомалар бүтін теңгемен (KZT).
Деректер: **3 шот, 15 категория, 180 транзакция, 3 бюджет**.
GitHub-қа топ өзі жариялайды; кодта GitHub API, логиндер немесе жариялау автоматтандыруы жоқ.

## Жылдам іске қосу

ZIP-ті ашып, терминалды `financial_manager` бумасында ашыңыз.

Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app/main.py
```

Python 3.12 немесе жаңарақ орнатылса, бірінші командада `py -3.12` не `python` қолданыңыз.
Виртуалды ортаны белсендіру міндетті емес: жоғарыдағы командалар оны тікелей қолданады.

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app/main.py
```

Браузерде `http://localhost:8501` ашылады. Тоқтату: терминалда Ctrl+C.
Бірінші орнатуға интернет керек; орнатылғаннан кейін қолданба интернетсіз жұмыс істейді.
Тексерілген нақты нұсқаларды қайталау үшін `requirements.txt` орнына
`requirements-lock.txt` қолдануға болады.

## Тексеру

Windows-та:

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m black --check .
.venv\Scripts\python.exe -m ruff check .
```

Орта белсендірілген кезде PDF-тегі қысқа командалар да жарайды:

```bash
pytest -q
black --check .
ruff check .
```

Тек бір зертхана: `python -m pytest tests/test_lab2.py -q`.
Соңғы нақты тексерулер: [CHECK_RESULTS.md](CHECK_RESULTS.md).

## Мәзір және не көрсету керек

Streamlit-тің стандартты бүйір мәзірі қолданылады. Жабық болса, сол жақ үстіндегі көрсеткіні басыңыз.

| Мәзір | Әрекет | Зертхана |
|---|---|---|
| Жалпы шолу / Overview | Сандар, бастапқы және қазіргі баланс | 1 |
| Деректер / Data | Кестелер, бюджет лимитін жаңарту, JSON жүктеу, seed-ке қайту | 1 |
| Функционалды ядро / Functional Core | `reduce` баланс, immutable қосу үлгісі; Maybe іздеу; транзакция валидациясы | 1, 2, 4 |
| Конвейерлер / Pipelines | Категория, күн, таңбалы сома сүзгілері; иерархия шығыны | 2 |
| Асинхрондық және оқиғалар / Async/FRP | Кейінгі зертханалар туралы түсіндірме | 5–8 кейін |
| Есептер / Reports | Forecast (cached), үш уақыт өлшемі, hits/misses; бюджет есебі | 3, 4 |
| Тесттер / Tests | Тексеру командалары және тест файлдары | 1–4 |
| Жоба туралы / About | Қысқаша түсіндірме және нұсқаулықтар | 1–4 |

## Есептеу ережелері

1. **Шот балансы.** `Account.balance` — бастапқы сома. `account_balance(trans, acc_id)`
   тек сол шот транзакцияларын `filter` және `reduce` арқылы қосады.
   Overview қазіргі балансты бастапқы баланс + транзакциялар ретінде көрсетеді.
2. **Immutable.** Домен модельдері `@dataclass(frozen=True)`, жинақтар `tuple`.
   `add_transaction` және `update_budget` жаңа tuple қайтарады. Қайталанған ID,
   жоқ бюджет немесе теріс лимит `ValueError` береді. UI жарамды шектермен жұмыс істейді.
   `Event.payload` ішіндегі dict/list те қорғалған mapping/tuple-ға айналады.
3. **Таза ядро және I/O.** `load_seed` файл оқитын шекара, сондықтан қатаң мағынада
   таза функция емес. UI, seed генераторы және уақыт өлшеу де сыртқы қабат.
   Есептеу функциялары кірістерін өзгертпейді. Кэш тек өнімділікке әсер етеді.
4. **Сүзгілер.** Күн — `YYYY-MM-DD`; екі шекара да кіреді.
   Сома таңбасымен салыстырылады: мысалы, −5000..−1000 — шығыстар.
   `by_category` тек дәл ID-ді сүзеді; барлық ұрпақ есебін рекурсия бөлек жасайды.
5. **Рекурсия.** `flatten_categories` түбірдің өзін, кейін ұрпағын береді.
   `sum_expenses_recursive` түбір мен ұрпақтағы теріс сомалардың модулін қосады.
   Жоқ түбір → бос tuple/0; цикл → түсінікті `ValueError`.
6. **Болжам.** `period` — 1..120 ай. Тірек — барлық транзакциялардың соңғы күні.
   Соңғы N күнтізбелік айдағы бір категорияның шығыны N-ге бөлінеді.
   Бос айлар да кіреді, нәтиже бүтін теңгеге төмен дөңгелектенеді.
   Бұл әдіс тарихи айлық орташа шығынды есептейді. Категория ұрпақтары бұл функцияда қосылмайды.
7. **Мемоизация.** Кілт `(cat_id, tuple[Transaction,...], period)` — hashable.
   Транзакция қосылса, жаңа tuple жаңа кілт болады. `lru_cache(maxsize=128, typed=True)` қолданылды:
   `True` және `1` кілттері араласпайды.
   Уақыт: кэшсіз бір шақыру; суық кэш бір шақыру; жылы кэш 30 шақырудың орташа ms-і.
   Өлшеу басында кэш тазартылады. Жылдамдық әр машинада әртүрлі, тесттер жылдамдықты мәжбүрлемейді.
8. **Бюджет.** Бір бюджет **бір нақты категорияға** тиесілі. Ай — күнтізбелік ай,
   апта — дүйсенбі..жексенбі. Есептің әдепкі тірегі — барлық транзакциялардың соңғы күні.
   Транзакция енгізгенде оның **өз күні** қолданылады, өткен айдың лимиті де дұрыс тексеріледі.
   Лимитке тең болу рұқсат, асып кету `Left` береді.
9. **Валидация.** `validate_transaction` шот, валюта, категория, бүтін нөл емес сома,
   кіріс/шығыс таңбасы, күн және ID тексереді. `validate_pipeline` оған қайталанған ID
   және сол категорияға қатысты барлық бюджет тексерулерін `bind` арқылы жалғайды.
   Қате → `Left({code, message, ...})`; жетіспейтін категория → `Maybe(None)`.
   Қалыпты жолда `try/except` жоқ. `Maybe(None)` — Nothing, `Maybe(0)` — бар мән.
10. **Сақтау.** Қосу/өзгерту тек браузер сессиясында. `seed.json` автоматты өзгермейді.
    Data → JSON жүктеу арқылы көшірме сақтаңыз; қайта қолдану үшін сол файлды
    `data/seed.json` орнына қойып, серверді қайта бастаңыз. JSON импорттаудың жеке UI-і жоқ.

## Үш студент және тапсыру

Тұрақты файл иелері мен ортақ функция келісімдері [TEAM_PLAN.md](docs/TEAM_PLAN.md) ішінде.
Осы дайын жоба — оқу және бірге түсініп қорғау негізі.
Әр студент өзі жасаған өзгерістерді, тест тексерулерін және қорғауда түсіндіретін бөлігін README-ге жазады.

Төрт жеке PR мен бейне сценарийлері [SUBMISSION.md](docs/SUBMISSION.md) ішінде.
Архивтің `lab_snapshots/` бумасында төрт тексерілген **жинақталған кезең** бар:
№1 тек №1; №2 №1+№2; №3 №1+№2+№3; №4 толық жоба.
Оларды қатарынан қолдансаңыз, әр PR-да жаңа зертхана ғана қосылады.
