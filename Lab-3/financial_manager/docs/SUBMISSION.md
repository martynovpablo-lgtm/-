# Төрт PR және төрт қысқа бейне

Жариялау мен бейне жазуды топ өзі орындайды. Бұл архивте дайын сыртқы PR немесе бейне жоқ.
Тек соңғы кодты төрт рет бірдей PR етіп жіберу дұрыс кезеңдік тапсыру болмайды.
Сондықтан архивте төрт **жинақталған, іске қосылатын** snapshot бар.

## Кезеңдерді дұрыс пайдалану

1. GitHub-та топқа бір репозиторий ашыңыз. Бастапқы `main`-да тек қысқа кіріспе болуы мүмкін.
2. `main`-нан `lab-01` жасаңыз. `lab_snapshots/lab-01.zip` ішіндегі жоба файлдарын
   репозиторийдің түбіріне көшіріңіз. `financial_manager/financial_manager` болып қабаттап қоймаңыз.
3. №1 тексерулерді орындап, PR ашып, екі студенттің қарауынан кейін біріктіріңіз.
4. Жаңартылған `main`-нан `lab-02` жасаңыз; №2 snapshot-пен файлдарды жаңартыңыз.
   №2-де №1 сақталады, оған №2 модульдері мен тесттері ғана қосылады.
5. Осы тәртіппен `lab-03`, кейін `lab-04`. Төртеуін де бос бастапқы main-нан қатар жасамаңыз.
6. Әр PR-ға экран жазбасына сілтеме қосыңыз. Соңғы main толық жобамен сәйкес болсын.

Snapshot ішінде негізгі app/main.py бар, қолжетімді lab деңгейін модульдерден анықтайды.
Болашақ кезеңнің бөлімдері түсіндірме көрсетеді. №4-де барлық алғашқы төрт зертхана жұмыс істейді.
Кезеңдік README оның нақты көлемін көрсетеді.

## PR сипаттамаларының дайын мазмұны

Төмендегі мәтіндерге өз нақты тексеру нәтижелеріңізді, студент есімдерін және бейне сілтемесін қосыңыз.

### lab-01 — Таза функциялар және immutable домен

Қосылды: frozen Account/Category/Transaction/Budget/Event, tuple деректер,
3 шот/15 категория/180 транзакция/3 бюджет seed; load_seed, add_transaction,
update_budget, account_balance; map/filter/reduce.

UI: Overview → көлем және баланс; Data → кестелер, лимитті сақтау;
Functional Core → шот балансын және immutable қосу үлгісін көрсету.
Күтілетін: ескі tuple сақталады, жаңа tuple қайтады; қазіргі баланс бастапқы балансқа транзакцияларды қосады.

Тексеру: `pytest -q`, `black --check .`, `ruff check .` нәтижесін тіркеу.
Бейне: топ жазған №1 скринкаст сілтемесі. Үлестер: кім қандай файлды түсіндірді/өзгертті/тексерді.

### lab-02 — Closure сүзгілері және екі рекурсия

Қосылды: by_category, by_date_range, by_amount_range; flatten_categories және
sum_expenses_recursive; кірістерді өзгертпейтін сүзгі конвейері.

UI: Pipelines → groceries, күн аралығы, теріс сома аралығы; түбір food.
Күтілетін: сүзілген кесте өзгереді, ағашта түбір мен ұрпақтар көрсетіледі;
шығын оң модуль ретінде есептеледі. Екі шекара сүзгіге кіреді.

Тексеру: барлық бар тесттер және стиль. Бейне: №2 сілтемесі. Нақты үлестерді қосу.

### lab-03 — Рекурсивті болжам және lru_cache

Қосылды: соңғы N күнтізбелік айдың орташа шығыны, бөліп есептеу рекурсиясы,
lru_cache immutable кілті, кэшсіз/суық/жылы кэштің ms өлшемдері.

UI: Reports → Forecast (cached) → категория/3 ай → «Болжам және кэш уақытын өлшеу».
Күтілетін: үш есептің нәтижесі тең, бір miss және 30 hit;
бос айлар орташаға кіреді. Уақыт нақты машинаға байланысты.

Тексеру: барлық бар тесттер, black және ruff. Бейне: №3 сілтемесі. Нақты үлестерді қосу.

### lab-04 — Maybe/Either және валидация

Қосылды: map/bind/get_or_else; safe_category, validate_transaction, check_budget;
ID/шот/категория/күн/сома/бюджет bind пайплайны, сессияға тек сәтті мәнді қосу.

UI: Functional Core → Maybe іздеу; жоқ шот, жоқ категория, шығыс үшін оң сома,
groceries үшін −1000000; кейін salary/+1000 және «сессияға сақтау».
Reports → бюджет есебін ашу. Overview → сәтті қосқаннан кейін 181 транзакция.
Күтілетін: қатеде Left және хабар; дұрыс жолда Right; бастапқы дерек бұзылмайды.

Тексеру: толық pytest, black, ruff. Бейне: №4 сілтемесі. Нақты үлестерді қосу.

## Қорғауда дайын жауаптар

- Неліктен tuple? Жинақты орнында өзгертпейміз; кэш кілті де hashable болады.
- Frozen жеткілікті ме? Ішкі mutable dict автоматты қатпайды; Event оны терең қатырады.
- `account_balance` нені есептейді? Тек транзакциялар қосындысын; бастапқы balance UI-де қосылады.
- Closure не сақтайды? Категория ID-і немесе аралық шектері predicate ортасында қалады.
- Рекурсияның тоқтауы? Баласы жоқ түбір/бір ай; әр қадам кіші құрылымға өтеді.
- Кэш ескі нәтиже бере ме? Жаңа Transaction tuple-ы жаңа кілт, ескі tuple өзгермейді.
- Maybe және Either айырмасы? Maybe — мән бар/жоқ; Either — сәтті мән немесе себебі бар қате.
- Неліктен bind? Келесі тексеру сәтті мәнге ғана орындалады, Left бірден өтеді.
- Бюджет қай кезеңде? Reports-та соңғы дерек күні; енгізуде жаңа транзакцияның өз кезеңі.
- GitHub-та кім не жасады? Нақты жазған/тексерген/түсіндірген жұмысты ғана атаңыз.
